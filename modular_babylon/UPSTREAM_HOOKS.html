Upstream integration hooks
modular_babylon/UPSTREAM_HOOKS.md

Babylon is opt-in: compile babylon.dme. The upstream tgstation.dme is unchanged. The fifteen modified upstream DM files use hooks guarded by BABYLON_BUILDER and marked BABYLON13. Ordinary SPLURT builds compile those blocks out.

The wrapper also defines upstream's ABSOLUTE_MINIMUM flag to skip the separate Interlink/cafe map loader. Builder behavior, restricted observer interfaces and lore papers live under modular_babylon; lore placements are applied to the fresh upstream map at preparation time, without a copied map.

Babylon is safe for work. modular_babylon/code/sfw.dm disables inherited ERP content through proc and var overrides only (no upstream edits): it locks DISABLE_ERP_PREFERENCES/DISABLE_LEWD_ITEMS on, filters lewd interactions, emotes, research designs and chemistry, removes the Plug13 verb, and opens the new Babylon-only tgui/packages/tgui/interfaces/BabylonInteraction.tsx instead of SPLURT's MobInteraction window. After an upstream merge, re-check newly added lewd interactions, designs, reactions and verbs against it.

Babylon has no storyteller yet. modular_babylon/code/storyteller.dm runs an inert /datum/storyteller/babylon in every world (no events, no antagonists), refuses the storyteller vote and any other storyteller, and keeps tgstation's random events off, again through overrides only. After an upstream merge, re-check SSgamemode's set_storyteller/init_storyteller, the storyteller vote and SSevents.spawnEvent against it; the native smoke test asserts it.

modular_babylon/code/moderation.dm grants lobby admins (BABYLON_ADMINS) full game-admin rights on admission, removes mentors (no mentor is loaded, admins are not made mentors, Mentorhelp and Mentorwho are gone) and relays adminhelps to the supervisor for the Discord ahelp feature; Discord replies use the game's external admin PM (TgsPm). All through overrides. After an upstream merge, re-check MessageNoRecipient, reply_to_admins_notification, receive_ahelp, TgsPm and the Skyrat mentor module against it.

modular_babylon/code/research.dm replaces the research point bank and queue: a techweb researches one selected node at a time, all income (through add_point_list) goes towards it capped at its price, research_points holds that progress, income without a target is dropped and switching targets starts over. The target is saved with the world. After an upstream merge, re-check add_point_list, research_node, complete_experiment, the queue procs and the R&D console / PDA research_node and ui_data against it. It also removes designs Babylon never offers (ERP, pAI, AI core, MMI, positronic brain) from every node in SSresearch.calculate_techweb_nodes and refuses them in /datum/techweb/add_design; /datum/techweb_node/Initialize is not usable for that, because upstream's initialize_all_techweb_nodes calls it on the old, empty node list.

modular_babylon/code/silicons.dm removes pAIs, station AIs, MMIs and positronic brains, which no one can play: pAI cards, AI cores and loose MMIs/posibrains delete themselves on creation (wreck, saves, loot), their designs are removed, the plasteel "AI core" recipe and the PDA vendor's pAI cards are gone, and ghosts get no "Enter Soulcatcher" button. After an upstream merge, re-check new sources of pAI cards, AI cores and ghost-joinable silicons against it.

modular_babylon/code/interface.dm trims the game window through overrides and runtime winsets (the shared interface/skin.dmf is unchanged): the top bar keeps Menu, Settings, Fullscreen and Reconnect; the station is named after the world (babylon-name, markup characters removed); the status tab drops the round ID; and verbs for systems Babylon lacks (antag tickets, OPFOR, round-end reports, votes, respawn, relays, forum/Discord-DB linking ...) are removed. After an upstream merge, check new player verbs and the infobuttons controls.

Keep these patches small. Do not copy complete upstream files from the local prototype. When upstream changes a hook's surrounding procedure, review its execution order, not just whether Git merges the text cleanly. In particular, moving restoration after simulation startup reintroduces reactor/network bugs.

Updating upstream

git remote add upstream https://github.com/SPLURT-Station/S.P.L.U.R.T-tg.git
git fetch upstream
git merge upstream/master

Skip remote add if the remote already exists. Preserve upstream history; do not squash upstream into this repository or force-push over its branches.

After every merge:

  1. Review every BABYLON13 marker and the standalone wrapper.
  2. Rename newly introduced .github/workflows/*.yml / *.yaml files with a .disabled suffix before pushing. Keep repository Actions disabled too.
  3. Compile ordinary tgstation.dme, production babylon.dme, and the local babylon-test.dme test build.
  4. Exercise a fresh wreck, a save/reload, pipe expansion, vent/alarm links, materials, airlock groups, and drone death/respawn. Use an isolated process and disposable world; never point tests at a player's running instance.

The private prototype's six upstream hooks were carried forward. Its chat transcript patch, personal config, owner name, repair object IDs, saved world, and training/admin subsystem were deliberately not imported.
